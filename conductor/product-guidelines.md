# Product Guidelines: WeatherGenerator

## 1. Communication & Prose Style
- **Technical & Formal:** Documentation, pull requests, and technical communications should be objective, professional, and precise. Avoid overly casual language to maintain the project's integrity as a scientific tool.

## 2. Documentation Standards
- **Comprehensive Coverage:** Documentation must address three primary pillars:
    - **Usage Examples:** Clear tutorials and quickstarts for common tasks (e.g., training, inference).
    - **Implementation Details:** Deep dives into the model architecture, data sampler, and distributed training logic.
    - **Scientific Foundations:** Rigorous documentation of the underlying physics, mathematical formulations, and datasets.

## 3. Coding Guidelines
- **Minimalist Commenting:** Code should be as self-documenting as possible through clear naming and modular design. Use comments only to explain non-obvious logic or scientific "magic numbers" that lack immediate context.

## 4. UX & API Design Principles
- **Ease of Use:** Prioritize simple and intuitive interfaces. The API should be accessible to climate scientists and researchers who may not be ML experts, abstracting away complex boilerplate while remaining flexible.
